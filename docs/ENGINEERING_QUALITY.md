# 工程质量与容量边界

本文记录 KAI Play 当前可重复的质量门禁、性能基线和仍需治理的边界。最近一次数据采集于 2026-08-31，命令均从仓库根目录执行。

## 架构边界

- `core/`：纯斗地主规则、状态机、公平承诺和玩家视图，不依赖 HTTP 或存储。
- `server/src/platform.ts`：身份、好友关系、房间、对局、幂等动作与结算用例编排。
- `server/src/server.ts`：HTTP 输入验证、限流、长轮询和优雅停机。
- `server/src/store.ts`：带校验和、原子替换和滚动备份的单进程 JSON 快照。
- `web/`：零第三方运行时依赖的浏览器客户端及同源代理；数独、象棋、扫雷、五子棋、记忆翻牌、贪吃蛇和 KAI 农场分别由独立规则模块承载生成、合法行动、终局或成熟与恢复状态转移；`catalog-carousel.js` 以纯函数承载筛选后索引、滚动目标、拖拽与释放吸附边界。
- `mobile/`：Expo SDK 57 客户端，消费同一套服务端权威接口。

斗地主竞技局的规则状态只由服务端推进。客户端倒计时使用响应里的权威 `turn.deadline`，动作携带 `expectedSequence` 和请求 ID；相同请求 ID 只有在载荷指纹一致时才可重放。返回的玩家视图和幂等缓存均与内部权威状态隔离。Web 共交付十五款玩法：斗地主是唯一服务端竞技局，其余十四款是明确隔离的本地免费训练，不请求服务端竞技结算。1048、数独、象棋、扫雷、五子棋、黑白棋、推箱子、数字华容道、记忆翻牌、贪吃蛇和 KAI 农场共十一款支持当前浏览器本地自动保存。

KAI 农场使用已保存的绝对成熟时间恢复离线成长；离线期间只改变作物是否成熟，不会自动发放金币。农场当前没有好友拜访、偷菜或跨设备同步，这些能力不得由客户端状态或发布文案暗示。

## 自动化门禁

```powershell
npm run build
npm test
npm run check
npm run preflight
npm run test:coverage
```

`npm run verify` 顺序执行 `build → test:coverage → check → preflight`；覆盖率命令本身已经运行全部测试。`build` 在当前阶段表示服务端/Web Node 可执行语法检查与移动端 TypeScript 检查，不表示 core/server 已完成 TypeScript 编译或生成发布产物。GitHub Actions 配置会在提交与拉取请求中安装 `mobile/package-lock.json` 锁定依赖、运行完整门禁、校验 Compose、构建两个容器镜像，并启动整套服务冒烟 API、Web 代理与视觉资产。发布预检还会校验安全边界、视觉资源、受信代理配置、文档和 CI 文件未被遗漏。

当前自动化测试覆盖规则单元测试、平台/存储集成测试、真实 HTTP 服务测试、Web 同源代理端到端测试，以及 1048、6×6 数独、KAI 象棋、KAI 扫雷、KAI 五子棋、KAI 黑白棋、KAI 推箱子、KAI 数字华容道、KAI 记忆翻牌、KAI 贪吃蛇和 KAI 农场的规则与产品交互契约。目录模块覆盖筛选后的可见顺序、不等宽卡片、首尾钳制、距离/速度翻页、纵向手势排除与 LTR/RTL 滚动模型；产品契约同时约束十五款玩法内容源、三手牌型判断、转轮会话统计、顶部四项导航和好友中心迁移。好友测试覆盖稳定 KAI 号、搜索关系状态、申请/接受/忽略、双向删除、旧存储迁移与真实 HTTP 契约；好友房继续验证创建/加入入口与现有服务端处理器复用。生产契约还会验证独立玩法模块的 Brotli、JavaScript MIME、CSP 与 ETag。

下表保留扫雷合流时最近一次可完整监听端口环境的覆盖率基线，当时 `npm run verify` 共执行 218 个测试且全部通过；它不是本次新增三款玩法后的最新覆盖率，也未使用单文件覆盖率替代：

| 指标 | 提升前 | 扫雷基线 | 变化 |
| --- | ---: | ---: | ---: |
| 行覆盖率 | 89.09% | 97.87% | +8.78 个百分点 |
| 分支覆盖率 | 79.63% | 87.51% | +7.88 个百分点 |
| 函数覆盖率 | 88.92% | 95.36% | +6.44 个百分点 |

表中只记录加入扫雷计时、多标签存档冲突、无障碍交互与生产传输契约后的历史结果。当前工作区 `npm run verify` 共执行 337 项测试且全部通过；本次 Node 原生报告为行覆盖率 98.14%、分支覆盖率 88.36%、函数覆盖率 96.03%。并发 HTTP/超时测试可能令覆盖率出现轻微时序差异，发布判断以每次 `npm run verify` 是否同时满足三项门槛为准。

发布门槛固定为行覆盖率 90%、分支覆盖率 80%、函数覆盖率 90%；低于任一阈值时 `npm run test:coverage` 和 CI 会直接失败。当前 Node 报告覆盖被测试进程加载的 `core/*`、`server/*`、`web/casual-games.js`、`web/catalog-carousel.js`、`web/sudoku6.js`、`web/xiangqi.js`、`web/minesweeper.js`、`web/gomoku.js`、`web/memory-match.js`、`web/snake.js`、`web/farm.js`、`web/serve.mjs` 及测试文件；不包含主要通过源码契约和真实浏览器回归验证的 `web/app.js`，也不包含 React Native UI。因此表中数字不能表述为全项目覆盖率，后续仍需迁移到能合并浏览器与移动端结果的工具。

覆盖率相对较低的剩余区域是机器人启发式的低概率分支和 CloudPay 沙盒提供方异常分支。当前环境没有真实 React Native 设备自动化；移动端通过类型检查、接口契约测试与共享 HTTP 集成测试覆盖，正式发布前仍应在 iOS/Android 真机执行冒烟回归。

## Web 传输性能

在同一台开发机、本地回环网络和相同静态文件下复测：

| 资源/行为 | 提升前 | 当前 | 结果 |
| --- | ---: | ---: | ---: |
| `styles.css` 传输量 | 207,578 B | 55,729 B（Brotli） | -73.2% |
| `app.js` 传输量 | 69,228 B | 45,129 B（Brotli） | -34.8% |
| 重复条件请求 | 200 + 完整正文 | 304 + 0 B | 消除重复传输 |
| JPG Content-Type | `application/octet-stream` | `image/jpeg` | 浏览器可正确处理 |

最终 20 次本机采样的响应耗时：CSS 中位 2.13 ms / P95 2.84 ms，JavaScript 中位 1.48 ms / P95 2.12 ms，JPG 中位 0.27 ms / P95 0.55 ms。活动牌局的每秒计时更新现在只修改倒计时节点，不再重建整棵页面 DOM。

这些数据是 HTTP 传输和本地响应指标，不是 Core Web Vitals；本次环境没有可用的 Chrome 性能追踪与真实移动设备，因此不能据此声称 LCP、CLS 或 INP 达标。

启动 Web 后可用 `npm run benchmark:web -- http://127.0.0.1:8081/ 20` 重复采样。脚本同时验证 Brotli、ETag、JPG MIME、CSP 和 `nosniff`，任一传输契约回归都会非零退出。

## 稳定性与安全改进

- 普通 Web/移动 API 请求有覆盖响应正文解析的 12 秒超时；长轮询使用 30 秒客户端上限并保留独立的服务端权威等待时间。
- 同步对短暂故障执行带抖动的指数退避，对 401/403/404 停止重试并展示错误。
- Web 与移动端只接受同一牌局中 sequence 单调递增的响应，避免较旧动作响应覆盖长轮询已经收到的新状态。
- Web 启动时只有明确的 401 才清除游客令牌，临时断网不会丢失身份。
- 三张翻牌、转轮和麻将机器人定时器均绑定当前玩法实例，离开或重开后旧回调不会污染新局。
- 扫雷从第一次有效揭格才开始计时；弹窗和标签页隐藏期间暂停，并保留暂停前不足一秒的有效用时。
- 扫雷本地存档使用乐观快照校验；另一标签页已有更新时，旧标签会停止写入并给出可见提示，避免静默覆盖最新棋局。
- Web 默认覆盖而不是信任客户端提供的 `X-Forwarded-For`；只有位于会清洗该头的受控 HTTPS 代理后方时才启用 `DOUJOY_WEB_TRUST_PROXY`，服务端也仅在显式 `DOUJOY_TRUST_PROXY=true` 时采纳。
- 静态服务提供 CSP、类型保护、路径校验、压缩、ETag 和请求中断传播。
- 服务端和 Web 的 SIGTERM/SIGINT 会停止接收新连接、终止活动代理/长轮询，并在宽限期内完成关闭。
- 相同幂等键的并发动作共享同一个落盘 Promise；快照失败时所有等待者都失败，并移除不可持久化的缓存结果。

## 单机容量边界

当前 JSON 存储只适合单实例和小规模发布。同一份 1000 个游客、每人创建一局的 fixture 中，旧版主快照约 9.98 MiB，紧凑 JSON 后为 4.65 MiB（-53.4%）；主文件加三代备份由约 39.9 MiB 降为 18.61 MiB。当前三次稳态保存为 325.89、328.82、316.99 ms，中位 325.89 ms；旧版 460.76 ms 只有一次样本，因此约 29.3% 的方向性改善不是 SLO 保证。该 fixture 没有动作，体积改善来自紧凑 JSON；512 条全局幂等结果上限由独立测试验证。用户、对局、房间、流水和报告仍按产品记录长期保留。

生产环境应监控主快照大小、保存耗时、磁盘余量和活动长轮询数。主快照接近 10 MiB 或保存 P95 接近 250 ms 时，应停止继续扩容并迁移 PostgreSQL；不要在没有产品数据保留决策时静默删除用户历史。迁移前不支持多实例、共享网络文件系统或滚动多副本发布。

## 已知技术债与后续里程碑

1. 将用户、会话、游戏、房间、账本和幂等键迁移到支持事务与唯一约束的数据库，解决内存先变更而落盘失败时的原子性边界。
2. 把 `web/app.js`、`web/styles.css` 和 `mobile/App.tsx` 按网络同步、状态、页面与牌面组件拆分；视觉回归稳定后再删除被覆盖的旧材质。
3. 增加结构化请求日志、快照保存耗时/大小、长轮询数量、就绪状态和告警；补充真实浏览器 Core Web Vitals 与 iOS/Android 端到端回归。
4. 接入依赖漏洞审计和 SBOM。当前离线环境无法查询最新漏洞库，因此本次报告不作“依赖无已知漏洞”的声明。
5. 为 core/server 增加锁定版本的根级 TypeScript 与 Node 类型、修复严格类型检查结果；当前门禁只能保证 Node strip-types 可执行语法与运行测试。
6. 当前 512 条幂等结果是全局最近窗口；被淘汰的旧请求不会重复执行，但只能得到 `STALE_GAME`，迁移数据库时应改为按玩家/牌局设置可观测的 TTL 与配额。

本次本地门禁运行在 Node v22.23.1 与 npm 10.9.8，仓库为 Git checkout；当前主机没有 Docker 或 actionlint，因此容器镜像和 GitHub Actions 仍需以远端 CI 的实际结果为准。CI 配置、Docker 路径以及数独、象棋、扫雷、农场等独立模块的生产拷贝契约均由静态预检覆盖。
