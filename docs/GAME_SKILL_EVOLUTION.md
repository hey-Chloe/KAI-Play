# Game Skill 自改进第一版

本轮接在真实农场与 Agent Lab 共用的 `skill_memory` 策略中，不新增一套演示游戏。它从已执行轨迹识别经济损失，构造受约束的策略候选，在隔离的规则状态中验证，通过后保存版本供下一局使用。新策略确实能够改变动作，而不只是显示一条“学会了”的文案。

## 最短闭环

完成一季 → 发现无法在第九日结束前收获的播种 → 比较两个白名单修订（停止迟播 / 换成来得及收获的作物）→ 六个合法起始状态均不退步且总收益严格提升 → 启用下一版本 → 每次改动动作前再次验证 → 退步则停用并隔离该候选。

这属于有限模板空间中的轨迹驱动策略修订，不是任意代码生成、模型权重训练或通用自主 Skill Discovery。模型服务不参与离线试跑，也不会产生模型 Token 费用。

## 可复现对照

运行 `npm run agent:eval`，或 `node scripts/evaluate-game-agent.mjs --json`。本轮机器报告保存在 `evals/kai-farm-skills-v1/report.json`。

| 起始状态 | 原策略金币 | 修订后金币 |
| --- | ---: | ---: |
| 第三日接管，发现轨迹与下一局对照 | 81 | 181 |
| 第四日接管，未参与候选选择的探针 | 96 | 166 |
| 第六日接管，未参与候选选择的探针 | 41 | 111 |
| 正常第一日开始 | 346 | 346 |

第三日重放实际改变五次动作。候选选择使用正常开局、第二日、第七日、第八日、有成熟作物、当日行动受限共六种状态；第四日和第六日只做冻结版本后的检查。这些都是相同农场规则的确定性结果，不证明跨游戏泛化。迟接管场景仍未达到 330 金币金牌目标，不能把收益提升说成任务已经成功。

## 在游戏里使用

新开一季，先手动推进到第三日，再点“开始托管”。本季结束后，已有反馈区域会说明是否通过自改进验收。以后托管默认读取浏览器本地版本；再次从第三日接管，会应用收获期限修订。正常路线没有迟播证据时不会虚构一次升级。Agent Lab 的 Skill + Memory 模式也使用同一个实现。

版本跟随现有本地 Memory 保存，可通过原有清除记忆操作重置；不上传、不跨设备同步。刷新恢复时重新验证版本来源与规则测试套件，过期或无效版本回退基线，真实农场与 Lab 均保存回退结果。

## 安全与计算边界

- 候选只是白名单数据，不执行存储内容或模型生成代码。
- 试跑使用克隆状态，不消耗玩家金币、不改变实际存档。
- 每条试跑最多 96 步；单次候选评测最多 12 个场景。
- 默认两个候选、六个场景，共 24 条试跑；恢复验证和每次动作反事实检查也计入 `skillTrialRollouts` / `skillTrialSteps`，不隐藏学习成本。
- `evolvedActions` 只计算成功执行的策略改动，不计算被守卫阻止或故障注入替换的动作。
- VLM 守卫先于策略与状态修改执行，视觉冲突仍然暂停。
- 历史最多保留 20 条；当前状态验证退步时隔离候选，后续学习不自动重新启用它。

下一阶段可以扩充独立场景与候选类型，再比较收益、泛化和运行成本。本版没有 SFT/RL、通用神经策略、MCTS、World Model，也没有证明 VLM 提升任务成功率。
