# KAI PLAY Product + UX V2

## 目标与成功条件

KAI PLAY 是中文优先的 AI 牌桌与益智游戏中心。用户打开后应在 3 秒内理解当前有 8 款真实可玩内容，并能在一次主要操作后进入精选、继续中的或任一目录玩法。

核心闭环：

```text
打开 → 选择或继续玩法 → 开局 → 对局 → 结算 → 再来一局或换个口味
```

## 产品路由

- 主原型：Consumer App
- 路由级原型：Live Game Lobby、Game Surface、Match Result、Season Record
- 主任务重心：Operate
- 次任务重心：Investigate（战绩与复盘）
- 主导对象：可加入的牌桌；进入牌局后切换为真实牌桌状态
- 品牌模式：supplied product brand；不加载其他 KAI 或 XIAOYUE 品牌视觉

## Art Direction

因为用户需要快速找到一局并持续操作，KAI PLAY 大厅采用“精选舞台 + 继续游玩 + 快速入口 + 海报卡目录”的发现结构；进入玩法后再切换为牌桌或棋盘主导构图。视觉使用克制的深色游戏封面、清晰中文爽点文案和由状态驱动的反馈动效，呈现“现在就能玩”的现场感；避免虚假在线人数、评分、热度、过量渐变与重复胶囊标签。

## Game Center V10 信息架构

大厅固定顺序：

1. 价值主张与按心情选择：短局放松、动脑解谜、棋桌对战、牌桌对战、和朋友玩。
2. 精选玩法：斗地主与麻将手动切换，不自动抢焦点。
3. 继续游玩：只读取扫雷、数独、1048 或象棋仍可继续的真实本地进度，并优先展示最近打开的玩法；已结束的棋局只在目录卡提供“查看上局”，不得继续占用续玩位；没有进行中存档时显示新手推荐。
4. 快速入口：首屏保留四个不同玩法的一次点击入口。
5. 全部玩法：八张等宽海报卡保持一排横滑，桌面约露出 4.2 张，手机约露出 1.1 张。
6. 好友房与战绩：作为低频工具放在目录之后；零场次时使用正向空状态，不前置展示 0% 胜率。

卡片文案优先表达体验结果和真实边界，只使用“编辑选择、新上线、可继续、首击安全、每日一局”等产品自有信号，不伪造在线人数、评分或算法推荐。

顶部保障只承诺可核验的能力：当前应明确写为“4 款本地自动保存”，不得用不带数量或范围的“本地自动保存”暗示八款玩法均有相同保存能力。

## 真实性边界

- 不展示服务端没有提供的在线人数、好友在线、排行榜名次或全国百分位。
- “智能牌友已就位”来自快速局真实的两名服务端机器人。
- 战绩、胜率、分数变化、连胜与趋势只从当前用户资料和历史记录计算。
- 当前没有逐手策略模型和完整回放数据，因此结算页只提供基于真实局面字段的规则级复盘预览；不得伪称为完整 AI 策略分析。
- CloudPay 和 KAI 卡时退出首页主路径；普通对局不付费。
- Web 大厅共提供八款可玩入口：斗地主写入服务端竞技战绩，其余七款均为本地免费训练。KAI 象棋与 KAI 扫雷只在 Web 提供本地对弈或益智训练，不请求服务端结算，也不改变竞技分、Token 或 KAI 卡时。
- “继续游玩”只接受已有可核验操作进度的进行中存档：扫雷为 `playing` 且至少揭开一格，数独为 `playing` 且至少一个可编辑格已有非零输入，1048 为 `playing` 且已移动至少一步，象棋为 `playing` 且已有一步棋或历史记录。最近玩法标记只决定这些有效候选项的排序，不能把刚打开但尚未操作、已完成、胜利、失败或结束状态包装成进行中进度。
- 移动端当前仍只交付斗地主闭环，不得因 Web 象棋或扫雷上线而展示无法进入的移动端入口。

## 四个核心 Surface

1. **Game Center Lobby**：精选玩法、真实续玩进度和八款目录共同构成发现主路径；好友房与战绩是目录后的次级工具。
2. **斗地主牌桌**：服务端权威牌局、座位、手牌、倒计时、轮次、最近行动与退出恢复保持完整。
3. **Match Result**：显示真实胜负、真实分数变化、规则级复盘预览、再来一局和返回大厅。
4. **我的战绩**：真实段位、竞技分、胜率、近期趋势、连胜和最近牌局；当前没有真实赛季周期，不使用“赛季”语义；无数据时提供开局路径。

## 排版与动效

- 使用系统 UI 字体与中文本地 fallback，不分发外部字体文件。
- 操作型字号保持克制；竞技分、倒计时和结算变化使用等宽数字。
- 动效只承担反馈、连续性、进度和少量注意力提示。
- 发牌、选牌、轮次、匹配、玩家就位、结算与分数变化必须有静态状态替代。
- `prefers-reduced-motion: reduce` 下移除持续位移、翻转、弹跳和装饰循环。

## 响应式与验收

- 桌面目标：1440×1000；精选舞台、继续游玩和至少四张目录封面在一次自然滚动内可见。
- 移动目标：390×844；首屏必须看到主 CTA、至少三个不同玩法入口、“全部玩法”标题和第一张卡片露边；另做 320×650 CSS px 短屏检查。
- 大厅的心情入口、主 CTA、续玩 CTA、快速入口、目录翻页、卡片 CTA 和底部导航触控目标至少 44×44 CSS px；320 CSS px 下“全部玩法”标题必须允许自然折行且不得与页码或翻页按钮重叠。象棋等密集棋盘在 320 CSS px 下保持整盘可见，交点目标不小于 24×24 CSS px，并提供清晰的选中、落点与键盘焦点反馈。
- 必测：Lobby、开局发牌、玩家轮次、对手轮次、完成结算、战绩有数据/空状态、象棋选子/落子/机器人应手/恢复、扫雷揭格/旗标/胜负/恢复、键盘焦点和 Reduced Motion。
- 最终门禁：真实浏览器桌面与移动端渲染、核心流程走通、控制台无错误、自动化测试与发布预检通过。
