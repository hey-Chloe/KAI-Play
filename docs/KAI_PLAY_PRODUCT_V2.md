# KAI PLAY Product + UX V2

## 目标与成功条件

KAI PLAY 是中文优先的 AI 牌桌游乐场。用户打开后应在 3 秒内理解当前可玩的游戏，并在一次主要操作后进入斗地主牌桌。

核心闭环：

```text
打开 → 发现可加入牌桌 → 开局 → 对局 → 结算 → 复盘 → 再来一局
```

## 产品路由

- 主原型：Consumer App
- 路由级原型：Live Game Lobby、Game Surface、Match Result、Season Record
- 主任务重心：Operate
- 次任务重心：Investigate（战绩与复盘）
- 主导对象：可加入的牌桌；进入牌局后切换为真实牌桌状态
- 品牌模式：supplied product brand；不加载其他 KAI 或 XIAOYUE 品牌视觉

## Art Direction

因为用户需要快速找到一局并持续操作，KAI PLAY 应通过牌桌主导构图、明确座位与轮次、紧凑中文操作排版、克制的深色桌面材质和由状态驱动的反馈动效，呈现“现在就能玩”的现场感；避免营销 Hero、等权功能卡、装饰性英文、虚假在线人数、过量渐变与重复胶囊标签。

## 真实性边界

- 不展示服务端没有提供的在线人数、好友在线、排行榜名次或全国百分位。
- “智能牌友已就位”来自快速局真实的两名服务端机器人。
- 战绩、胜率、分数变化、连胜与趋势只从当前用户资料和历史记录计算。
- 当前没有逐手策略模型和完整回放数据，因此结算页只提供基于真实局面字段的规则级复盘预览；不得伪称为完整 AI 策略分析。
- CloudPay 和 KAI 卡时退出首页主路径；普通对局不付费。
- Web 大厅共提供七款可玩入口：斗地主写入服务端竞技战绩，其余六款均为本地免费训练。KAI 象棋只在 Web 提供本地人机对弈，不请求服务端结算，也不改变竞技分、Token 或 KAI 卡时。
- 移动端当前仍只交付斗地主闭环，不得因 Web 象棋上线而展示一个无法进入的移动端入口。

## 四个核心 Surface

1. **Live Lobby**：可立即加入的斗地主牌桌是第一视觉主体；快速开局与好友房为稳定行动。
2. **斗地主牌桌**：服务端权威牌局、座位、手牌、倒计时、轮次、最近行动与退出恢复保持完整。
3. **Match Result**：显示真实胜负、真实分数变化、规则级复盘预览、再来一局和返回大厅。
4. **我的战绩**：真实段位、竞技分、胜率、近期趋势、连胜和最近牌局；当前没有真实赛季周期，不使用“赛季”语义；无数据时提供开局路径。

## 排版与动效

- 使用系统 UI 字体与中文本地 fallback，不分发外部字体文件。
- 操作型字号保持克制；竞技分、倒计时和结算变化使用等宽数字。
- 动效只承担反馈、连续性、进度和少量注意力提示。
- 发牌、选牌、轮次、匹配、玩家就位、结算与分数变化必须有静态状态替代。
- `prefers-reduced-motion: reduce` 下移除持续位移、翻转、弹跳和装饰循环。

## 响应式与验收

- 桌面目标：1440×1000。
- 移动目标：390×844；另做 320 CSS px 重排检查。
- 核心行动按钮触控目标至少 44×44 CSS px；象棋等密集棋盘在 320 CSS px 下保持整盘可见，交点目标不小于 24×24 CSS px，并提供清晰的选中、落点与键盘焦点反馈。
- 必测：Lobby、开局发牌、玩家轮次、对手轮次、完成结算、战绩有数据/空状态、象棋选子/落子/机器人应手/恢复、键盘焦点和 Reduced Motion。
- 最终门禁：真实浏览器桌面与移动端渲染、核心流程走通、控制台无错误、自动化测试与发布预检通过。
