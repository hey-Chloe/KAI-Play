# KAI PLAY Product + UX V2

## 目标与成功条件

KAI PLAY 是中文优先的 AI 牌桌、策略、益智与经营游戏中心。用户打开后应在 3 秒内理解当前有 12 款真实可玩内容，并能在一次主要操作后进入精选、继续中的或任一目录玩法。

核心闭环：

```text
打开 → 选择或继续玩法 → 开局 → 对局 → 结算 → 再来一局或换个口味
```

## 产品路由

- 主原型：Consumer App
- 路由级原型：Live Game Lobby、Game Surface、Match Result、Season Record
- 主任务重心：Operate
- 次任务重心：Investigate（战绩与复盘）
- 主导对象：可加入的牌桌；进入牌局后切换为真实牌桌状态
- 品牌模式：supplied product brand；不加载其他 KAI 或 XIAOYUE 品牌视觉

## Art Direction

因为用户需要快速找到一局并持续操作，KAI PLAY 大厅采用“精选舞台 + 继续游玩 + 快速入口 + 海报卡目录”的发现结构；进入玩法后再切换为牌桌或棋盘主导构图。视觉使用克制的深色游戏封面、清晰中文爽点文案和由状态驱动的反馈动效，呈现“现在就能玩”的现场感；避免虚假在线人数、评分、热度、过量渐变与重复胶囊标签。

## Game Center V10 信息架构

大厅固定顺序：

1. 价值主张与按心情选择：短局放松、动脑解谜、棋桌对战、牌桌对战、和朋友玩。
2. 精选玩法：斗地主与麻将手动切换，不自动抢焦点。
3. 继续游玩：只读取扫雷、数独、1048、象棋、五子棋、记忆翻牌、贪吃蛇或 KAI 农场仍可继续的真实本地进度，并优先展示最近打开的玩法；已结束的棋局或轮次只在目录卡提供“查看上局”，不得继续占用续玩位；没有进行中存档时显示新手推荐。
4. 快速入口：首屏保留四个不同玩法的一次点击入口。
5. 全部玩法：十二张等宽海报卡保持一排横滑，桌面约露出 4.2 张，手机约露出 1.1 张。
6. 社交与战绩：大厅内容流只保留“和朋友玩”轻入口；好友、好友房和战绩摘要进入独立好友中心，避免打断找游戏的主路径。

卡片文案优先表达体验结果和真实边界，只使用“编辑选择、新上线、可继续、首击安全、每日一局”等产品自有信号，不伪造在线人数、评分或算法推荐。

顶部保障只承诺可核验的能力：当前应明确写为“8 款本地自动保存”，不得用不带数量或范围的“本地自动保存”暗示十二款玩法均有相同保存能力。

## Portal Discovery V15

在保留 KAI 实体牌桌与棋盘质感的前提下，大厅吸收中文小游戏门户的快速扫读效率，以及现代游戏中心的常驻搜索和意图筛选：

1. 首屏搜索覆盖游戏名称、中文别名、英文名与真实玩法标签；按 `/` 可直接聚焦，`Escape` 清空当前搜索。
2. 目录提供“全部、可继续、5 分钟、牌桌、棋类、益智、街机、自动保存”八种本地筛选，不请求服务端、不上传搜索内容。
3. “可继续”只匹配目录卡上已经由真实存档判定产生的“可继续”状态，不把刚打开、已结束或零进度的局面算入结果。
4. 保留单排横向卡牌结构与触摸滑动；桌面卡片压缩到约五张同时可见，手机保留下一张露边提示，兼顾快速比较与原有滑动偏好。
5. 精选牌桌的展示高度降低，搜索、心情入口和更多游戏封面更早进入首屏；不新增虚假的“热门”“猜你喜欢”或在线人数。
6. 搜索无结果时必须显示明确空状态与“一键显示全部”，结果数量通过 `aria-live` 对辅助技术播报。

V15 是 V10 目录结构的增量升级，仍保持“介绍 → 精选与续玩 → 全部玩法”的大厅语义顺序、十二款固定目录顺序和每张卡一个真实主操作；社交与战绩由顶部主导航进入各自页面。

## Returning Player & Poster V16

1. 仅当至少存在一项真实、未结束且已有操作进度的本地存档时，大厅才进入“回访优先”状态；窄屏续玩面板排列在精选牌桌之前，桌面采用左侧续玩、右侧精选，视觉顺序与键盘顺序一致。
2. 多项存档显示真实的“`N` 款可继续”，按可继续的玩法种类计数；点击后清空搜索、启用现有“可继续”筛选并滚动到目录，零进度、终局或损坏存档不计数。
3. 精选舞台继续承担斗地主与麻将入口，右侧快速入口不再重复两款精选玩法，改为 1048、五子棋、记忆翻牌和贪吃蛇。
4. 目录卡仍保持一排滑动与原有密度，但封面增高、主体按玩法分别缩放，并提高标题和元信息可读性；细指针悬停只提供轻微景深反馈，触屏和减少动态效果模式不依赖动画。

## Local Farm V17

1. “KAI 农场”是浏览器本地经营玩法，核心闭环为播种、浇水、等待成熟、手动收获，再用所得金币投入下一季；不借用第三方品牌、角色或美术资产。
2. 农场状态在当前浏览器自动保存，离开页面后根据保存的成熟时间继续计算成长；成熟本身不会自动发放金币，玩家必须返回并收获。
3. 玩法不请求服务端竞技结算，也不改变竞技分、Token 或 KAI 卡时；当前不支持好友拜访、偷菜、排行榜或跨设备同步，不得以文案或假数据暗示这些能力已经存在。
4. 只有已播种、已浇水、已有收获或其他可核验操作进度的农场存档才进入“继续游玩”，零进度的新农场不占续玩位。

## Gameplay Depth & Catalog Motion V18

1. 十二款玩法共用一份可审计的玩法内容源，统一给出目标、核心循环、完成条件、预计时长、参与模式、保存范围和当前能力边界；大厅“当前玩法”面板与规则页完整手册必须复用该内容源，不能出现两套相互矛盾的说明。
2. 全部玩法继续保持用户指定的单排卡片轨道：桌面同时展示约五张，手机展示一张主卡并露出下一张。箭头、键盘、鼠标拖拽、触屏原生滑动与筛选后的定位共享同一套卡片索引和边界钳制；拖拽结束吸附到最近的有效卡片，拖动不能误触发卡片开局。
3. 当前卡片提供明确层级，并同步更新页码、玩法名称、首尾箭头状态和下方玩法速览；筛选优先保留仍然可见的当前卡，不再无条件把轨道跳回起点。
4. 炸金花训练改成三手牌型判断：玩家必须先观察手牌并选择牌型，随后揭晓三家牌面；会话只记录真实的判断正确数、独胜手数和并列数，并正确处理同牌力并列。
5. 算力转轮保留大厅彩蛋定位，新增本次页面会话的旋转次数、共振值、最佳组合、已见符号和不同组合数；这些数字仅是不可兑换的娱乐记录，不进入竞技分、Token、卡时或任何支付系统。
6. 麻将目录文案只承诺现有的摸牌、弃牌与受支持和牌型，明确当前不含吃碰杠和完整番型计分；五子棋、农场和其他玩法同样必须如实描述难度、社交和存档边界。

V18 响应式验收目标为 1440×1000、390×844 与 320×700：标题与页码不得重叠，页面不得产生横向溢出，所有主要操作不小于 44×44 CSS px，减少动态效果模式下禁用平滑滚动和卡片位移动画。

## Top Navigation & Friend Center V20–V21

1. “游戏、战绩、规则、好友”四项主导航属于页面顶部栏：桌面与品牌、玩家信息同排，平板和手机在品牌行下方保持四项横排；不得再次固定到视口底部或覆盖页面内容。
2. 大厅移除原目录后的好友房/战绩工具区，只在心情入口保留“和朋友玩”；原好友房入口和战绩摘要迁入好友中心。
3. 好友中心使用真实服务端关系：每位游客拥有稳定 KAI 号，支持按完整 KAI 号或昵称搜索、发送好友申请、接受、忽略、查看双向好友列表与删除好友；不读取设备通讯录。
4. “开房邀请”只创建真实六位房号并提示用户自行分享。当前没有站内聊天、在线状态或自动发送邀请，不得用虚假红点、在线人数或消息状态模拟这些能力。
5. 创建、加入、恢复、房间同步和服务端判定继续复用现有权威房间 API；已入房后的 `room` 页面保持独立轮询与确认退出，不能通过普通导航绕过离房请求。
6. 六位房号在进入忙碌状态前完成校验，并保留本地草稿；房间不存在、已开局或暂时无法访问时，用户输入不得因页面重绘而丢失。输入框支持回车加入，并过滤非数字字符。
7. 1280、390 与 320 CSS px 下顶部导航均保持四项横排、按钮高度不小于 44px、页面无横向溢出；窄屏好友资料、目录、申请与房间任务依次单列。

## 真实性边界

- 不展示服务端没有提供的在线人数、好友在线、排行榜名次或全国百分位。
- KAI 号、好友申请和好友关系来自服务端持久化状态；当前好友页不代表通讯录同步、在线状态或即时消息已经开放。
- “智能牌友已就位”来自快速局真实的两名服务端机器人。
- 战绩、胜率、分数变化、连胜与趋势只从当前用户资料和历史记录计算。
- 当前没有逐手策略模型和完整回放数据，因此结算页只提供基于真实局面字段的规则级复盘预览；不得伪称为完整 AI 策略分析。
- CloudPay 和 KAI 卡时退出首页主路径；普通对局不付费。
- Web 大厅共提供十二款可玩入口：斗地主是唯一写入服务端竞技战绩的竞技玩法，其余十一款均为本地免费训练。KAI 象棋、五子棋、扫雷、记忆翻牌、贪吃蛇与 KAI 农场只在 Web 提供本地对弈、益智、即时操作或经营训练，不请求服务端结算，也不改变竞技分、Token 或 KAI 卡时。
- “继续游玩”只接受已有可核验操作进度的进行中存档：扫雷为 `playing` 且至少揭开一格，数独为 `playing` 且至少一个可编辑格已有非零输入，1048 为 `playing` 且已移动至少一步，象棋与五子棋为 `playing` 且至少落下一步，记忆翻牌为 `playing` 且至少翻开过卡片或完成一对配对，贪吃蛇为 `playing` 或 `paused` 且至少移动一格，KAI 农场为至少完成播种、浇水或收获中的一项。最近玩法标记只决定这些有效候选项的排序，不能把刚打开但尚未操作、已完成、胜利、失败或结束状态包装成进行中进度。
- 移动端当前仍只交付斗地主闭环，不得因 Web 象棋或扫雷上线而展示无法进入的移动端入口。

## 五个核心 Surface

1. **Game Center Lobby**：精选玩法、真实续玩进度和十二款目录共同构成发现主路径；社交只保留“和朋友玩”轻量跳转。
2. **好友中心与等待房**：管理 KAI 号、搜索、申请和好友关系，并独立完成创建/六位房号加入；进入房间后展示真实座位、同步状态、分享房号、房主开局和确认退出。
3. **斗地主牌桌**：服务端权威牌局、座位、手牌、倒计时、轮次、最近行动与退出恢复保持完整。
4. **Match Result**：显示真实胜负、真实分数变化、规则级复盘预览、再来一局和返回大厅。
5. **我的战绩**：真实段位、竞技分、胜率、近期趋势、连胜和最近牌局；当前没有真实赛季周期，不使用“赛季”语义；无数据时提供开局路径。

## 排版与动效

- 使用系统 UI 字体与中文本地 fallback，不分发外部字体文件。
- 操作型字号保持克制；竞技分、倒计时和结算变化使用等宽数字。
- 动效只承担反馈、连续性、进度和少量注意力提示。
- 发牌、选牌、轮次、匹配、玩家就位、结算与分数变化必须有静态状态替代。
- `prefers-reduced-motion: reduce` 下移除持续位移、翻转、弹跳和装饰循环。

## 响应式与验收

- 桌面目标：1440×1000；精选舞台、继续游玩和至少四张目录封面在一次自然滚动内可见。
- 移动目标：390×844；首屏必须看到主 CTA、至少三个不同玩法入口、“全部玩法”标题和第一张卡片露边；另做 320×650 CSS px 短屏检查。
- 大厅的心情入口、主 CTA、续玩 CTA、快速入口、目录翻页、卡片 CTA 和顶部导航触控目标至少 44×44 CSS px；320 CSS px 下“全部玩法”标题必须允许自然折行且不得与页码或翻页按钮重叠。象棋等密集棋盘在 320 CSS px 下保持整盘可见，交点目标不小于 24×24 CSS px，并提供清晰的选中、落点与键盘焦点反馈。
- 必测：Lobby、开局发牌、玩家轮次、对手轮次、完成结算、战绩有数据/空状态，以及象棋、五子棋、扫雷、记忆翻牌、贪吃蛇和 KAI 农场的核心状态、恢复、键盘/触控与 Reduced Motion。
- 最终门禁：真实浏览器桌面与移动端渲染、核心流程走通、控制台无错误、自动化测试与发布预检通过。
