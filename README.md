# KAI Play（算力局）

一个免费开局、服务端判定并支持断线恢复的原创多游戏产品。历史字段 `balance` 在产品中统一解释为“竞技分”，不可充值、提现、转让或兑换。KAI 卡时只允许购买未来可明确交付的 AI、托管和个性化服务，不参与牌局输赢；当前版本没有真实卡时扣减。

## 当前闭环

- 游客身份与 10,000 初始竞技分
- 可完整进行的斗地主：一名玩家和两名服务端机器人，或六位房号好友房与机器人补位
- 二十五款即开即玩的 Web 玩法：斗地主竞技局，以及 KAI 象棋、KAI 五子棋、KAI 黑白棋、四人基础麻将、1048、6×6 KAI 数独、KAI 扫雷、KAI 推箱子、KAI 数字华容道、KAI 记忆翻牌、KAI 三消、KAI 方块、KAI 贪吃蛇、KAI 迷宫、KAI 农场、KAI 井字棋、KAI 点灯、KAI 猜数字、KAI 猜拳、KAI 心算、KAI 顺序记忆、KAI 颜色挑战、炸金花和算力转轮二十四款免费训练
- 游戏中心支持中文/英文别名即时搜索，以及可继续、5 分钟、牌桌、棋类、益智、街机和自动保存筛选；“全部玩法”以类似中文小游戏门户的小图标网格展示，桌面与手机分别按可用宽度快速排布
- 小图标入口均可直接开局，筛选结果会原位重排而不劫持页面横向手势；规则页提供二十五款游戏的完整目标、循环、终局、时长与保存边界
- Web 主导航固定在页面顶部；好友中心提供稳定 KAI 号、昵称/KAI 号搜索、好友申请、接受/忽略、双向好友列表和删除好友，并承载好友房与战绩摘要
- 好友房可从大厅“和朋友玩”或顶部“好友”进入；六位房号输入在请求失败后仍会保留，当前不虚构好友在线、站内聊天或自动发送邀请
- 回访用户优先看到真实续玩入口，并可一键筛出全部可继续玩法；新用户首屏快捷入口覆盖 1048、五子棋、记忆翻牌与贪吃蛇，不重复精选牌桌
- 1048、数独、象棋、扫雷、五子棋、黑白棋、推箱子、数字华容道、记忆翻牌、三消、方块、贪吃蛇、迷宫与 KAI 农场共十四款玩法支持当前浏览器本地自动保存
- KAI 数独支持入门/标准/挑战、每日一局、候选笔记、撤销、提示、最佳用时与本地自动保存
- KAI 象棋提供 9×10 棋盘的人机对弈，由玩家执红先行；规则、机器人与进度均在本地运行，不请求竞技结算
- KAI 扫雷提供本地单人逻辑训练、旗标和自动存档；玩法不请求竞技结算，也不改变竞技分
- KAI 五子棋提供 15×15 本地人机对弈；玩家执黑，KAI 会优先取胜与封堵五连
- KAI 记忆翻牌提供三档牌阵、计步计时、最佳成绩与自动恢复；KAI 贪吃蛇提供三档速度、键盘/滑动/触控方向键与本地最佳分
- KAI 三消提供 8×8 宝石盘、有效交换、连锁补充与步数目标；KAI 方块提供七种经典方块、旋转、消行与等级加速；KAI 迷宫提供三档可解盘面、最短路线提示与步数对比
- KAI 农场提供单人九日丰收挑战：每天 5 次行动，围绕播种、浇水、缺水杂草、三种作物解锁、旺需行情和赛季奖章形成约 5–8 分钟闭环；当前不支持好友拜访、偷菜或跨设备同步
- KAI 农场的真实游戏页已接入 Agent 托管：玩家可让 Agent 只走一步、连续托管或随时暂停；Agent 操作的是当前同一份农场状态，继续使用原规则、原本地存档与原交互结果，不会另开一局模拟。托管完成后，结算页会展示决策数、Skill 覆盖、视觉核对、守卫停手和本地 Memory 结果。Agent Lab 同时保留完整研究视图，支持画面/文本/RPC 状态融合、目标分解、层级规划、Skill Library、失败注入与自动恢复，并把最近 20 个已完成 Episode 保存在当前浏览器；成功轨迹会被归纳为可解释的 Skill 宏，在下一轮作为计划先验检索。第四个对照策略会在每个真实动作前执行 64 次受预算约束的 UCT-MCTS rollout，并显示固定种子、树深、扩展节点、根动作访问数和价值。可选接入独立的 Qwen2.5-VL + ScienceQA LoRA 服务读取真实像素帧；模型在线时，农场托管会在每步执行前启用视觉守卫，冲突或服务不可用都会先停手且不修改存档。当前 MCTS 使用农场领域先验和精确规则 simulator；本地轨迹归纳不等于模型训练，也不代表该跨域模型已具备游戏策略能力，当前未接入 LLM、RL 或 learned World Model
- 炸金花训练提供三手牌型判断、三家揭晓、正确率与并列统计；算力转轮提供仅限本次会话的组合收集与共振值，不支付、不下注且没有可兑换奖励
- 定主位、三张增补牌、组合牌型、特殊组合翻倍和零和结算
- 服务端权威校验、顺序号防陈旧写入、带载荷指纹的幂等动作
- 开局牌序哈希承诺，结束后公开 nonce 与牌序供复核
- Expo SDK 57 移动端大厅、牌桌、好友房、战绩和规则说明
- 零依赖 Web 界面，通过同源代理连接同一套服务端
- 默认关闭的 CloudPay 卡时计费骨架；沙盒模式也不会发起真实支付或访问 CloudPay

## 本地运行

要求 Node.js 22.18+。首次克隆后，在仓库根目录安装移动端锁定依赖：

```powershell
cd KAI-Play-repo
npm ci --prefix mobile
```

浏览器版本使用同源 `/api` 代理。在两个终端从仓库根目录启动：

```powershell
npm run server
```

```powershell
npm run web
```

打开 `http://127.0.0.1:8081/`。Web 默认把 `/api` 代理到 `http://127.0.0.1:4310`；后端使用其他端口时设置 `DOUJOY_WEB_UPSTREAM`。

移动端从 `mobile` 目录启动：

```powershell
cd mobile
npx expo start
```

Android 模拟器默认访问 `http://10.0.2.2:4310`；iOS 模拟器默认访问 `http://127.0.0.1:4310`。真机调试时设置 `EXPO_PUBLIC_DOUJOY_API_URL=http://你的电脑局域网IP:4310`。

## 容器运行

```powershell
docker compose up --build
```

容器同时启动游戏服务端和浏览器界面。默认仅绑定本机：界面为 `http://127.0.0.1:8081`，API 为 `http://127.0.0.1:4310`；状态写入独立的 `doujoy-data` 卷。公网部署必须使用会覆盖 `X-Forwarded-For` 的 HTTPS 反向代理，并将 `DOUJOY_CORS_ORIGIN` 设置为实际 Web 来源；同时仅在这条受控链路上设置 `DOUJOY_WEB_TRUST_PROXY=true`。生产模式缺少 CORS 来源时服务端会拒绝启动。

单机存储会写入带版本与校验和的原子快照，并默认保留三代滚动备份。该模式只支持一个服务端实例；多实例或跨机器容灾必须迁移到事务数据库。

## 构建与验证

```powershell
npm run build
npm run verify
npm run test:coverage
npm run agent:eval
```

`build` 会检查服务端和 Web 的 Node 可执行语法，并执行移动端 TypeScript 检查；`verify` 还会运行带 90%/80%/90% 门槛的覆盖率测试、规则完整性与发布预检。CI 配置会在每次提交和拉取请求中重复这些步骤，校验 Compose、构建两个容器镜像，并启动整套服务冒烟 `/health`、Web 代理和视觉资产；首次推送后仍应以 GitHub Actions 的实际结果为准。

本仓库不包含真实卡时扣减、充值、提现、链上 Token、玩家间转账或随机现实价值奖励。真实 CloudPay 接入前必须迁移到 PostgreSQL 事务账本、完成服务间认证与 Webhook 签名、关闭沙盒完成入口，并取得产品、安全和法务批准。
